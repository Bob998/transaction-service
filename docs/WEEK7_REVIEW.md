# 第7周复盘

本周完成了从交易创建到日终对账的业务闭环。系统能够通过唯一幂等键阻止重复交易，使用 Aviator 执行可配置风控规则，根据通道健康、成本与成功率动态路由，并在首选通道故障时切换备用通道。

支付超时时不直接判失败，也不盲目重试，而是记录 `UNKNOWN` 并交给查询或对账确认。交易成功、账务流水和 Outbox 事件依靠数据库事务及唯一约束保障一致性。日终对账可以发现缺单和金额差异，处理动作全程留存审计记录。

这一周最重要的认识是：Redis、Kafka、分布式锁和第三方通道都只能提供能力，金融正确性的最终基础仍是数据库唯一约束、明确状态机、可靠事务、幂等设计、账务记录和可追溯审计。
